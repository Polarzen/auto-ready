# Auto Ready

Auto Ready 是 Windows 上的单轮准备按钮助手。默认只提醒；你手动开始一轮后，它才等待按钮出现。自动确认每轮最多尝试一次点击，不会自动开始下一轮。

当前版本为 **0.4.2**，支持配置名称和游戏标签，修正已保存模板的载入和复用，增加模板预览，并避免重复保存相同图片。便携包见 [v0.4.2 Release](https://github.com/Polarzen/auto-ready/releases/tag/v0.4.2)。实际验证范围以 [STATUS.md](STATUS.md) 为准；自建窗口的捕获结果不代表真实游戏兼容性。

## 第一次使用

1. 选择 **设置当前配置**，在向导中确认当前游戏窗口。同名窗口可通过进程名称区分；每次启动都要确认实际目标。需要另一份配置时选择 **新建配置…**。
2. 获取一张画面，直接框出“准备”或“接受”按钮。画面是静态的，可以重新获取、重新框选和撤销。WGC 可用时直接获取目标画面；前台兼容方式会提示倒计时和手动切回。
3. 做 **无点击检查**。向导会说明找到一个按钮、找到多个相似区域或暂未找到，并给出下一步建议。没有出现按钮时可以返回修改，也可以保留尚未确认的配置。
4. 填写 **配置名称** 和 **对应游戏**，然后 **保存配置并完成**。同一游戏可以有多份配置，例如“大厅准备”和“匹配接受”。回到主界面后仍是仅提醒、尚未开始。

成功标志是可选项。没有它也能完成设置，但后续只能报告“已尝试点击，结果未确认”。按钮消失不等于准备成功。

## 平时使用

选择已有配置 → 确认目标窗口 → **开始等待**。

主界面的 **当前配置的模板** 显示已经保存的按钮图片；**查看模板…** 可以在未选择目标窗口时查看按钮和可选成功标志。载入配置会恢复模板和识别参数，兼容的目标只需重新确认窗口，不用再截图或框选。启动时会实际载入默认配置；载入未完成或失败时不能用空内容覆盖它。

**修改当前配置…** 用于调整现有配置，**高级设置** 和 **诊断** 提供截图、识别参数和技术信息。若窗口尺寸或 DPI 与保存时不同，模板仍保留并可预览，但需恢复原尺寸/DPI或重新调整模板才能开始。

- **仅提醒**：有效后台画面也可以识别和请求提醒，不移动鼠标、不输入、不主动切换窗口。通知发出不代表你已经看到或听到。
- **自动确认**：你明确选择该模式并开始本轮，才可能点击。未允许切回时，后台发现按钮会等待你手动返回游戏。
- **发现按钮后，允许切回游戏**：默认关闭，是本轮额外授权，可能打断当前操作。每轮最多请求一次正常切回；系统拒绝时只提醒，不反复抢焦点。授权不会写进配置。

后台识别、主动切回和实际点击是三种独立能力。切回后会丢弃后台候选，等待稳定的新画面并重新确认唯一按钮；不会把后台坐标排队补点。实际点击仍要求目标前台、按钮无遮挡、有效急停、身份/尺寸/DPI/帧时效正确，且没有按键或拖动冲突。

## 等待、停止和托盘

你可以最小化工具，或明确选择隐藏到托盘。托盘提供恢复主界面、简短状态、停止本轮和退出；通知默认不抢焦点。点击通知不会开始一轮或授权点击。

普通关闭按钮仍然停止并退出，不会悄悄在后台继续操作。默认全局停止键是 **Ctrl+Alt+F11**，主界面始终显示其状态并提供停止按钮。急停未注册时只允许提醒；自动确认必须实际注册成功，并在输入前再核对。F12 被 Windows 保留给调试器，旧配置中的 F12 需要明确改为其他键。

本轮默认超时 120 秒。手动暂停后只可手动继续，暂停时间仍计入原来的整轮超时；停止、超时或终态后用时固定。更换目标、配置、捕获方式或关键设置会取消本轮；启动、载入和完成向导都不会自动开始。

## 后台捕获的支持范围

| 情况 | 行为与边界 |
| --- | --- |
| 窗口未最小化，WGC 持续取得有效目标画面 | 可以非前台识别；遮挡物不会成为目标画面来源。实际兼容性仍须按当前窗口检查。 |
| WGC 接口/初始化不可用 | 显示“前台兼容捕获”及原因，使用 GDI 时需要目标前台且无遮挡。 |
| WGC 运行中无新源帧、黑屏或资源错误 | 暂停检测并说明原因，不用旧画面冒充实时监控，不偷偷继续宣称后台正常。 |
| 目标最小化 | 不承诺捕获或自动准备；请手动恢复。 |
| 受保护内容、独占全屏、HDR 或特殊窗口 | 不保证兼容；状态/诊断显示不可用或尚未验证。 |
| 同尺寸移动 | 等待几何稳定后重新识别，不要求仅因移动重框按钮。 |
| 尺寸/DPI 改变 | 原模板不再兼容，阻止输入并要求重新确认。 |

WGC 支持不等于每个游戏支持；新源帧也不证明游戏内部仍在推进。本次原生、源码、EXE、真实切回、真实输入和游戏验证分别记录在 [STATUS.md](STATUS.md)。

捕获使用 Windows Graphics Capture 的指定 HWND 接口和真实源帧时间。GDI 是屏幕兼容路径，不能在被遮挡时拿遮挡窗口的像素当作游戏。捕获工作在后台线程，未等待时不持续抓图。Windows 捕获边框可能由系统显示。

## 编辑和保存多份配置

主界面的配置列表按 **游戏 · 配置名称** 显示，下方始终显示当前配置和对应游戏。选择 **载入配置…** 可以按名称、游戏和文件位置选择已发现的配置；其他目录中的配置可通过 **浏览其他配置文件…** 打开。同名配置会显示文件信息以便区分。

选择 **重命名…** 可以修改配置名称和对应游戏，明确保存时也会保存当前配置的修改。名称保存在配置内容中，原 JSON 文件名和模板位置保持不变。**另存为…** 可以用新名称保存一份独立配置。取消或保存失败不会切换当前配置。

**修改当前配置…** 的向导会保留已有按钮图片、成功标志、名称和游戏标签；无需改动的模板可以直接沿用，保存更新当前 JSON。**新建配置…** 才会从空白配置开始并新增 JSON。在向导中成功载入其他配置后，会关闭当前草稿并回到主界面显示所选配置。

旧配置仍可载入：尚未命名时显示原文件名，默认文件显示“默认配置”，游戏显示“未标注游戏”；通过“重命名…”补充即可。对应游戏只是便于辨认的标签，每次启动仍需手动确认目标窗口。未保存修改会有标记，切换时可以保存、放弃或取消。向导的后退或取消不写入半成品，也不清除原配置。

高级设置保留搜索范围、成功标志、阈值、连续帧数、稳定时间、本轮超时、停止键、提示音、捕获方式和诊断。修改后需要重新开始本轮。

旧版默认配置 `%LOCALAPPDATA%\auto-ready\config.json` 和多份 JSON 仍兼容。新增字段只在内存中补默认值，明确保存才写盘。模板 PNG 保存在各 JSON 旁的 `templates\` 文件夹；**移动或备份配置时要同时带上 JSON 和 templates**。重复保存或重命名会复用相同图片；同目录的配置也可以共用相同内容的图片，修改模板不会覆盖其他配置引用的图片。历史图片不自动删除。配置不保存窗口绑定、运行中的会话、自动确认模式或切回权限。

截图用于内存中的识别，不自动上传或写盘。轮转日志位于 `%LOCALAPPDATA%\auto-ready\auto-ready.log`，最多 1 MiB，保留三份，不记录图片内容。

## 运行便携版与源码

本版正式构建目录为 `dist\releases\0.4.2\`，本地候选包和旧版目录保留。完整解压便携 ZIP 后运行 `auto-ready.exe`，保留旁边 `_internal`。先正常关闭自己正在使用的旧版，再运行新版。

源码需要 Windows x64 和 Python 3.11，依赖只装在项目虚拟环境：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-windows.lock.txt
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m auto_ready
```

本版使用固定的 `windows-capture==2.0.1`（MIT）和普通 `opencv-python`。HWND 后台捕获要求 Windows 10 1903 或更新系统。升级已有开发环境时，应先移除旧的 `opencv-python-headless`，避免两个发行包同时提供 `cv2`。便携包不需要另装 Python 或这些依赖。

```powershell
.\.venv\Scripts\python.exe -m auto_ready --simulator
```

普通模拟器用于熟悉配置流程，不自动选择目标或授权输入。受限历史验收入口 `--verify-simulator` 默认使用拒绝真实输入的适配器；本轮开发不执行 `--allow-real-input`，也不复用 v0.2.0 历史真实输入结果作为本版通过。

## 零输入后台捕获检查

```powershell
.\.venv\Scripts\python.exe -m auto_ready --capture-check --capture-check-output artifacts\capture-check.json
```

该入口只创建并捕获自己的标记窗口，不选择游戏，不发送鼠标/键盘输入，不主动切回。检查非前台、遮挡、静止画面、最小化/恢复、资源重建和关闭，并保存源帧、裁剪、时效、开销及退出证据。原生环境不可用时明确记录失败或待验证。便携 EXE 可使用同样参数；源码通过不能替代便携版检查。

人工验收时，先在仅提醒模式对实际目标做无点击检查，再观察非前台画面及提醒是否正确。真实切回和真实点击是另行授权、另行验证的项目。

## 构建与验证

```powershell
.\scripts\build_windows.ps1 -Zip -OutputDirectory "dist\releases\0.4.2"
```

构建执行全量测试、Ruff、依赖检查，再生成 PyInstaller onedir 和无输入启动检查。发行目录包含原生 WGC 扩展、依赖许可证、说明、示例及构建元数据。`build-info.json` 如实记录源码提交和 dirty 状态；`source-snapshot.zip` 与 JSON 清单精确标识未提交源码。ZIP 的 SHA-256 单独计算并保存。全量结果、实际包大小及 SHA-256 见 [STATUS.md](STATUS.md)。

## 保留的边界

这是局部图像识别，不是成功概率。相似界面、动画和缩放会造成漏判或误判；多候选拒绝操作。成功需要点击前没有、点击后连续出现的正向标志，按钮消失或 Windows 接受输入都不算成功。

最终检查与系统输入之间仍存在操作系统竞态，不能保证绝对不会误点。程序不做进程注入、内存读写、后台消息点击、驱动安装、游戏文件修改或反作弊规避；不扩展自动下一局、选角色或无人值守循环。

技术参考：[Microsoft 捕获指南](https://learn.microsoft.com/en-us/windows/apps/develop/media-authoring-processing/screen-capture)、[前台切换限制](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)、[SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)、[RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey)。
