# Auto Ready

Auto Ready 是一个 Windows 桌面工具：它在你明确选择的窗口客户区内识别准备按钮，并按所选模式提醒或执行一次鼠标点击。默认只提醒、未启用；只有切换到“自动确认”并手动开始本轮后才可能发送点击。它不连接服务器，也不会上传截图。

## 运行

便携版：完整解压 `dist\auto-ready-windows-x64.zip`，双击解压目录中的
`auto-ready\auto-ready.exe`，无需另装 Python。不要单独移动 EXE；须保留旁边的 `_internal` 目录。
从项目目录运行已构建程序和模拟器：

```powershell
.\dist\auto-ready\auto-ready.exe --simulator
```

源码运行：

要求 64 位 Windows 和 Python 3.11。所有依赖安装在项目 `.venv`，不需要全局安装：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m auto_ready
```

本机已验证的依赖版本记录在 `requirements-windows.lock.txt`。需要复现相同版本时，
在安装项目之前运行 `.\.venv\Scripts\python.exe -m pip install -r requirements-windows.lock.txt`。

打开主界面和模拟窗口：

```powershell
.\.venv\Scripts\python.exe -m auto_ready --simulator
```

也可以只运行模拟器：

```powershell
.\.venv\Scripts\python.exe -m auto_ready.simulator
```

## 基本流程

1. 每次启动都重新选目标窗口。点击“等待 3 秒并采集”，然后切回目标窗口；工具不会替你切换焦点。
2. 在预览中选择“按钮模板”并拖出准备按钮。可选地框选较小的“搜索区域”和一个“成功标志模板”；也可以导入图片作为模板。修改这些识别设置会取消当前轮。
3. 先用“无点击预览”检查候选框、匹配分数和拒绝原因。识别先用灰度归一化互相关筛选候选，再对每个候选计算彩色互相关与外观差异，并取三者中的最低分；这是保守的局部图像匹配分数，不是成功概率。[OpenCV `matchTemplate` 文档](https://docs.opencv.org/4.x/df/dfb/group__imgproc__object.html)
4. “仅提醒”不会发送输入。“自动确认”也不会自动启动：点击“手动开始本轮”才授权这一轮。每轮最多尝试一次点击；默认本轮超时为 120 秒。暂停后要手动继续；“停止本轮”或全局停止键会结束当前轮。
5. 若配置了成功标志，工具要求点击前没有该标志、点击后在新截图中连续识别到它，才报告成功。没有配置成功标志或超时会显示“结果未确认”；按钮消失本身不算成功。

默认全局停止键是 `Ctrl+Alt+F11`，每次启动和修改都必须实际注册成功。F12 被 Windows 保留给调试器，程序拒绝注册所有 F12 组合。[Microsoft `RegisterHotKey` 文档](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-registerhotkey)

旧配置中的 F12 会原样显示并提示迁移，自动确认保持禁用。你需要明确选择 F11 或其他非 F12 组合，确认“已注册”后才能使用自动确认；点击“明确保存配置和模板”才会保存变更。非 F12 的自定义配置保持原值。注册冲突时不自动换键，仅提醒仍可使用；修改热键会取消当前轮及排队中的开始请求。

## 本地数据

只有点击“明确保存配置和模板”才会写入配置；文件位于 `%LOCALAPPDATA%\auto-ready\config.json`，模板 PNG 位于同目录的 `templates\`。配置不会保存目标窗口绑定或本轮启用状态。截图只在内存中用于当前识别，不会自动保存。

桌面启动时会初始化轮转日志 `%LOCALAPPDATA%\auto-ready\auto-ready.log`，最多 1 MiB、保留 3 个轮转文件。日志不记录截图或图片内容。

## Windows 构建

先按上面的步骤准备 `.venv`，再运行：

```powershell
.\scripts\build_windows.ps1
```

脚本检查项目虚拟环境确为 64 位 Python 3.11，依次运行 `pytest`、Ruff、`pip check`，再用 PyInstaller 生成 `dist\auto-ready\` 的 onedir 窗口程序，并用 `--smoke-test` 启动打包结果。Smoke test 使用不发送输入的假后端，打开后自动关闭。加 `-Zip` 会额外生成 `dist\auto-ready-windows-x64.zip`。构建会把 README、状态文档、示例配置以及运行依赖许可证文本放入发行目录；许可证位于 `_internal\licenses`。构建阶段临时使用最小 PATH，防止其他工具的同名 DLL 被误打包，结束后恢复当前进程 PATH，不修改全局环境。

发行目录中的 `build-info.json` 记录应用版本、构建所用源码提交和当时工作区 dirty 状态；
ZIP 的大小与 SHA-256 另存于本地验收记录及同名 `.sha256` 文件。后续仅更新交付文档时，
应用源码提交仍以 `source_commit` 为准，文档提交另行记录。

## 限制与注意

- 目标必须位于前台、可见、未最小化，并且客户区可检查；遮挡或窗口状态不适合时会拒绝操作。移动窗口会清除当前连续识别计数，等待位置稳定后自动重新识别，无需重采模板。缩放、最大化或 DPI 改变后，模板尺寸不再兼容，需要重新采集模板。独占全屏、复杂叠窗和不同 DPI 的组合未保证可用。
- 识别依赖屏幕图像。多个候选会被拒绝；相似动画、色彩变化或界面缩放都可能导致误判或漏判。模板分数不是概率，也不构成成功证明。
- 自动点击通过 Windows `SendInput` 向系统输入流发送鼠标移动和一次按下/抬起；鼠标会留在目标位置，不会恢复原位置。物理鼠标键或修饰键按住时会拒绝输入。[Microsoft `SendInput` 文档](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-sendinput)
- 最后的窗口检查和系统输入之间仍可能发生焦点变化，这是操作系统层面的竞态。请勿把它当作可靠的游戏自动化或反作弊规避工具。
- 请自行确认目标游戏的规则。本项目不代表任何游戏厂商批准，也不保证账号安全；程序不做进程注入、内存读写或游戏文件修改。
- 专用模拟器上的受限真实输入 A/B/C 已分别在源码版和最终解压 EXE 完成验收；真实游戏场景仍未验证。普通自动化测试使用模拟界面和假输入。建议先使用 `--simulator` 熟悉流程，并保持默认“仅提醒”模式。

## 可选的模拟器真实输入验证

v0.2.0 的源码和便携版复用同一个受限验证模块、生产状态机和输入适配器。普通 `--simulator` 只打开模拟器，不代表授权真实输入。受限验证入口默认使用拒绝适配器：

```powershell
.\.venv\Scripts\python.exe scripts\verify_simulator.py
# 或便携版
.\dist\auto-ready\auto-ready.exe --verify-simulator
```

仅当你本人在现场决定允许真实输入时，手动执行以下其中一条命令。自动开发和打包检查不会运行它们：

```powershell
.\.venv\Scripts\python.exe scripts\verify_simulator.py --allow-real-input
# 或便携版；源码版验收不能替代这一步
.\dist\auto-ready\auto-ready.exe --verify-simulator --allow-real-input
```

此选项不会选择目标、采集模板、切换模式或开始本轮。你仍须手动选择专用模拟器、采集按钮模板、选择“自动确认”、点击“手动开始本轮”，再手动把模拟器置于前台。输入边界验证 HWND、PID、启动时间、可执行文件、前台、最新截图几何/新鲜度和客户区坐标；仍保留生产引擎的单次资格与取消检查。最后检查与输入之间仍有系统竞态。鼠标会停留在按钮位置，不恢复原位。

辅助程序使用 `%LOCALAPPDATA%\auto-ready\simulator-check\` 保存自己的配置和日志，不覆盖普通配置；与主应用共用单实例锁。关闭任一窗口都会关闭另一窗口，并停止线程、释放热键和锁。窗口列表只提供本次创建的专用模拟器，不能选择游戏、浏览器或其他进程。

每次运行的证据保存在隔离目录 `simulator-check\runs\<运行标识>\`，路径显示在验证界面中。记录包括身份、会话、DPI/几何、实际后端、点击资格消耗、SendInput 返回数量/释放清理、模拟器独立收到的按下/释放/点击事件、点击前后图像成功检测及最终状态。系统接受输入不等于目标收到点击，Qt 事件也不能代替图像成功证据。原始记录留在本地；分享前删除个人路径、进程身份等信息。默认不保存截图。

### 现场最小验收流程

先准备模板：在未启用状态手动显示准备按钮并采集按钮模板；若要验证成功，可手动点击模拟器进入成功画面，再采集成功标志模板，最后手动重置并显示准备按钮。模板准备期间的手动点击与本轮计数分开。确认模板尺寸、搜索区域和全局 F11 注册状态后，逐轮执行下表，每一行都重新手动开始，不能自动续轮。

| 场景 | 现场动作 | 独立核对证据 |
| --- | --- | --- |
| A 稳定窗口 | 选择成功场景，保持窗口稳定；切换自动确认，手动开始后自行切回模拟器 | 资格消耗 1 次、原生批次 1 次且插入 3 个事件、模拟器收到按下/释放/点击各 1 次；点击前成功标志不存在，之后新截图连续检测到成功，终态成功 |
| B 同尺寸平移 | 保留原模板，手动平移模拟器；大小和 DPI 不变；独立手动开始 | 模板尺寸键不变、窗口原点改变、实际输入点随位移变化；其余同 A，不重采模板、不使用旧坐标 |
| C 结果未确认 | 使用“未成功”场景并保留成功模板；或重新准备一份无成功模板配置；独立手动开始 | 至多一次尝试；无成功模板时立即未确认，未出现成功标志时等待验证超时；不得重试或显示成功 |

分别在源码版与最终解压 EXE 执行 A/B/C，记录运行标识、会话、计数、最终状态和原因。日志只呈现观察结果，不自动宣布验收通过；缺失证据记为未验证。允许输入却没有 OS 结果时使用 `UNVERIFIED_NO_OS_RESULT`；默认拒绝适配器使用 `NOT_EXECUTED`。终态后到达的 Qt 事件单独标记会话关联歧义。主动制造失焦、遮挡、旧帧等竞态使用假输入测试，不故意冒险向其他窗口发送真实输入。源码版及最终解压 EXE 的模拟器真实输入 A/B/C 均已通过；真实游戏仍为**未验证**。脱敏验收摘要见 [`STATUS.md`](STATUS.md)，本地原始证据位于 `artifacts/real-input-20261013-batch3/`。

只读桌面探测历史记录（v0.1.0）来自 Windows 11 build 26200、Python 3.11.9、PySide6 6.10.3 的 150% 缩放显示器（DPI 144）：模拟器客户区为 1080×795 物理像素、720×530 逻辑像素；首次截图耗时 24.41 ms，平移窗口后截图耗时 15.98 ms，合成按钮候选得分约为 1。探测中前台检查为 false 时没有执行输入；当时的 F12/F11 注册与释放成功（历史事实，不作为继续使用 F12 的依据），第二个实例锁请求被拒绝。这些是本机只读探测，不证明其他机器或游戏表现。

历史合成图像基准（v0.1.0）在单个 OpenCV 线程下运行：20 个 1920×1080 帧的中位识别耗时 42.26 ms、最大值 48.56 ms，四分之一尺寸 ROI 为 9.56 ms，详见 [`artifacts/benchmark.json`](artifacts/benchmark.json)。基准仅使用合成图像；未执行真实鼠标点击或游戏测试。

## 常见故障与检查

| 现象 | 处理 |
| --- | --- |
| 提示目标不在前台 | 手动切回目标；应用不会替你切换。正常采集提供 3 秒切换时间。 |
| 黑屏、空白、被遮挡或无法确认可见 | 使用普通窗口/无边框模式，完整露出目标客户区与按钮；不尝试绕过游戏限制。 |
| 无匹配或模板无效 | 重新采集含文字和边框的完整按钮，避免纯色区域；先做无点击预览。 |
| 多个候选 | 缩小窗口内搜索区域，使它只包含预期按钮；不要仅降低阈值。 |
| 客户区尺寸或 DPI 不兼容 | 在目标的当前大小/显示器重新采集按钮和成功模板；窗口仅平移无需重采。 |
| 自动确认不可选 | 查看“停止键状态”，换一个能注册的组合；注册失败时仅提醒仍可使用。 |
| 已尝试点击但结果未确认 | 本轮不会重试；检查实际界面，再手动开启新一轮。可配置明确的成功状态模板。 |
| 输入被系统拒绝 | 检查是否按住鼠标键/修饰键、目标是否有更高完整性权限。应用不会提权或绕过限制。 |
| 无提示音 | 点击“测试系统提示音”，检查 Windows 系统提示音和音量；系统静音时程序无法保证听到声音。 |
| 配置加载失败 | 查看界面和本地轮转日志；保留原配置，修复字段或重新明确保存，不会自动启用。 |

开发检查命令（均默认不会发送真实鼠标输入）：

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m auto_ready --smoke-test
.\.venv\Scripts\python.exe scripts\desktop_probe.py
.\.venv\Scripts\python.exe scripts\benchmark.py
```

`desktop_probe.py` 只打开并移动自己的模拟窗口，记录客户区坐标、截图、热键和互斥锁检查结果，
不会调用鼠标输入。探测/基准 JSON 写入被 Git 排除的 `artifacts\`；应用日常运行不保存截图。
最终交付和未验证项见 [STATUS.md](STATUS.md)。
